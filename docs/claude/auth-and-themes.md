# Auth and the Keycloak theme

Moved verbatim from the old CLAUDE.md (lines 289-290). Not loaded at session start: read it on demand, only when the task touches this area.

- **Auth:** shared Keycloak, realm `myapps`, client `finance-tracker`. The prod issuer is `https://auth.finance-nl.com/realms/myapps`. See `docs/auth.md`.
  - The auth theme (UX-15, D-613 to D-636): `../auth_server/deploy/themes/finance-tracker/` (`login/` on `keycloak.v2`, `account/` on `keycloak.v3`, `email/` on `keycloak`; no template copied but the email's HTML layout), mounted read-only into production's and the dev stack's Keycloak, its tokens copied from `frontend/src/index.css` (change them here first, then there) and its fonts the app's `@fontsource/ibm-plex-sans` 5.3.0 files. Its `js/theme.js` picks Blue, Light or Dark from the cookie `ft_theme`, else the device. The realm's `displayName` "Finance Tracker", its three themes `finance-tracker` and SMTP's sender name "Finance Tracker" are set by UX-15's checklist (rollback: `displayName` `myapps`, D-628; `keycloak.v2`, `keycloak.v3`, `keycloak`; `finance-nl.com`). auth_server's PRODUCTION.md, "Theme", has the rest; its README the dev realm's step and Mailpit (http://127.0.0.1:8025), which catches the dev realm's emails. `cd e2e && npm run screens:keycloak -- <folder>` (local only) takes every Keycloak page in each theme from throwaway dev realms.
