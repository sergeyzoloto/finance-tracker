# Backend class catalog and database migrations

Moved verbatim from the old CLAUDE.md (lines 124-243). Not loaded at session start: read it on demand, only when the task touches this area.

- **Backend** (`backend/`):
  - Stack: Java 21, Spring Boot 3.5, Maven wrapper, Spring Data **JDBC** (records, no JPA/Hibernate), Flyway, PostgreSQL.
  - Code lives in package `com.example.financetracker`. Every query of a ledger table is scoped by the `ledger_id` of a `LedgerScope` (ADR 0003, topic C); a row of another ledger returns 404. The repositories of ledger rows extend `ledger.LedgerScopedRepository`, which offers `save` and no lookup or delete by id alone. Callers use their default methods that take a `LedgerScope` (`find`, `findAll`, `lockAll` and so on); the derived queries with a raw ledger id behind them (`findByIdAndLedgerId` and the like) are called only from those. What is about the person (the `users` row, settings, manual rates, delete-all) is keyed by the user id.
  - `security/`: `SecurityConfig` makes the backend a BFF and an OAuth2 resource server. It runs oauth2Login with PKCE and keeps tokens in the session.
    - Every request's JWT is checked: issuer, `aud` = finance-tracker, a non-blank `sub`, and client role `user` → ROLE_USER (`ClientRoles`). Writes need the CSRF cookie and header.
    - `/actuator/health` (the only Actuator endpoint exposed) is open to everyone and says only UP or DOWN. The images' health checks call it; production's Caddy doesn't route `/actuator`.
    - `SessionAccessTokenFilter` turns the session token into a bearer token and refreshes it. It drops the session's login authentication, which grants nothing by itself. One request of a session refreshes at a time, under a lock kept in the session, and reads the tokens again under it; the others use its new token, since the realm accepts each refresh token once. A refused refresh ends the session only while the refused token is still the session's. The lock is in the JVM: one api instance.
    - A late second callback of a finished sign-in (`authorization_request_not_found` in a signed-in session) goes to `/?login=done`, not to the login-failed notice.
    - `CurrentUserResolver` is the one place that works out the user: it fills the `CurrentUser(id, name)` parameter of controller methods with the JWT `sub` (and the account's name, for display only). On first sight of a user it provisions them (`UserDataService.provision`: the `users` row with email and name, then `StarterLedger.seedIfNew`). After `UserDataDeleted` commits it forgets the user, so their next request provisions them again.
    - `PersonalLedgerResolver` fills a `LedgerScope` parameter with the user's personal ledger (`LedgerAccess.personal`), after `CurrentUserResolver` has provisioned them. Controllers pass the scope to services that read or write ledger rows, and the user id to those about the person.
    - `MeController` serves GET `/api/me`: the name, the token's `email` (D-54, F8b; the end-to-end suite's identity check compares it), `timeZone` (null until set) and `today` in it (D-101, F8c: the frontend uses no other today), `dateFormat` (D-304, UX-1: null for as the browser shows dates), `features.familyLedgers`, the family switch's state, for the frontend, and (UX-15, D-619, additive) `accountUrl`, Keycloak's account console `<issuer>/account?referrer=<client id>` built from `app.keycloak.*` (the client id URL-encoded), whose "Back to Finance Tracker" Keycloak 26.7 resolves to the client's base URL (no `referrer_uri`, no redirect URI added; D-623).
  - `api/`: what all endpoints share.
    - `ApiExceptionHandler` is the one `@RestControllerAdvice`. Every error is an RFC 7807 problem detail: 400 with `errors` (field, message), also for a parameter value that no handler takes (a report's `currency`), 404 for another user's object, 409 for a stale version or a conflicting change (with `code` for one the client tells apart: `LAST_OWNER`, F6a; `ENTRIES_AFTER_RETURN`, F6b), 429 with `Retry-After` for too many attempts (`TooManyRequestsException`, F5's invites), 422 with `violations` for broken ledger rules (for the family budget's rules also `violationDetails`: `code`, `memberId`, `message`), 500 without details. The family endpoints' messages are the screens' words: "family budget", shares as percentages with two decimals (`ledger.family.BasisPoints`).
    - `JsonConfiguration` writes every `BigDecimal` as a JSON string. `@CurrencyCode` validates ISO 4217 codes.
    - `OpenApiConfiguration`: springdoc serves the OpenAPI 3.1 description at `/api/openapi`, behind login like the rest of `/api`.

ECB rates stay. It publishes `UserDataDeleted`. The Keycloak account is untouched.
    - Exceptions for the API: `NotFoundException` (404), `ConflictException` (409), `RuleViolationException` (422, one or more violations).
