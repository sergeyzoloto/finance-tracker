# Finance Tracker

## Definition of done

1. Every task that changes files ends with a new entry at the top of [change_log.mdx](change_log.mdx), in its existing format: what changed, how it was verified, and what is still open, with the commit it landed in ("Not committed yet." until then).
   - The heading is `## YYYY-MM-DD · Title`, followed by the commit line and the sections **Changes**, **Verified** and **Open**. Newest first; never edit an older entry.
   - It is MDX: a bare `{` or `<` breaks it. Put code, paths, endpoints, class names and generics in backticks.
2. The "Done when" part of a task prompt adds conditions to this rule and never replaces it.
3. The final report of every task quotes the new change log entry.
4. (D-97) The final report states, for each test suite the task ran, the command, its exit status and its whole summary (the Tests and Errors lines, or Maven's Results). A suite "passed" only with exit status 0, however its summary reads: F8b reported "312 passed" while `npm test` exited 1 with `Errors 1 error`.
5. (D-734) `scripts/check-forbidden-names.sh`: before every commit the working tree (no argument) exits 0, and after it `--log <the stage's base>..HEAD` exits 0; exit 2 (the names file is missing) is reported to the owner, never skipped.

A Stop hook (`.claude/hooks/require-changelog.sh`, registered in `.claude/settings.json`) keeps Claude from finishing while files in the working tree changed but `change_log.mdx` did not.

## Git

Never use `git stash`. For a temporary check, copy the files aside and back, or use a scratch worktree (`git worktree add`, removed afterwards).

## The agent's shell

D-55 (after OPS-2b's report: a heredoc ran lines as shell with empty variables). For every command the agent runs on the laptop:

- A heredoc only with a quoted delimiter (`<<'EOF'`), so that nothing in it is expanded or run.
- Every scratch script starts with `set -euo pipefail`.
- In any command that writes, moves or deletes, a path built from a variable is written `${VAR:?}`, so that an empty variable stops the command instead of widening it (`rm -rf "${DIR:?}/x"`).

## Docker on the laptop

Never run `docker … prune` of any kind (`system`, `image`, `container`, `volume`, `network`, `builder`): OPS-2 ran `docker volume prune -f` on the laptop, which removed every unused anonymous volume, not only its own. Remove only the resources you created, by name or by a label you set (`docker rm -f -v <name>`, `docker rmi <repository:tag>`, `docker network rm <name>`, `docker volume rm <name>`), and leave images you found already there. This is about the commands the agent runs; `deploy.sh`'s own `docker image prune -f` on the server (its step 3.5) is the deploy scripts', unchanged. (D-940, OPS-5) On the server only the deploy scripts' own prunes run, by the scripts and by no one's hand or checklist: `docker image prune -f` (step 3.5) and `docker builder prune -f --filter until=72h --reserved-space 3GB` (step 3.7, and `deploy/deploy.sh prune-cache`), which touch dangling images and build cache only; never `system`, `volume`, `container` or `network` prune, `-a` or `--volumes` there, since both stacks' Postgres volumes live on that host. (D-948, OPS-6) Old images of the server are removed only by a checklist's own part, after a read-only listing of what uses them: `docker image rm` of exact tags written out in full, and of untagged images by the IDs the PM fills in, only when no container uses them; `postgres:17.11`, the previous api and web tags and every pin in use stay (D-947).

## Production safety

Production is the auth server's host, which this app shares. On 2026-09-28 a `sed` range in an auth repository task ran part of that repository's `PRODUCTION.md` as bash on the server, prose included, since the backticks of inline code turn prose into command substitutions. Among other things it reinstalled, removed and reinstalled this app's site file (see [change_log.mdx](change_log.mdx) and the auth repository's `change_log.mdx`, D4-IR). Rules for every task:

- Never run text extracted from a document or file on a server: no `sed`, `awk` or `grep` output, and no variable filled from a file. Check a documented command by reading it, or by running it in a throwaway local container. This applies to every command the agent runs and every command it writes into a deploy checklist, where commits are named explicitly. The runbook's generic blocks for the human operator ("Update the app", "Roll an update back") may read `/root/finance-tracker.previous`; they print the commit they read before they use it.
- Write every server command out explicitly on the command line. Never pipe a file or a heredoc into a remote shell (`ssh host bash -s < file`, `ssh host 'bash -s' <<'EOF'`, `… | ssh host bash`).
- The one exception is the deploy scripts (OPS-1): `deploy/deploy.sh` and `deploy/rollback.sh`, with `deploy/common.sh`, are committed, reviewed and tested (`deploy/tests/`), and the operator runs them on the server as files, from its clone. They run SQL only from the committed check files `deploy/checks/*.sql` (and the role's own description, `ROLE_SQL` in `deploy/common.sh`), through `psql` as the read-only database role `finance_checks` (since F6b: no superuser, a member of `pg_read_all_data` only, `default_transaction_read_only = on` set on the role, no password; created once by the runbook's command, "A read-only role for the deploy checks"), with `PGOPTIONS=-c default_transaction_read_only=on` as well; they stop when the role is missing, is a superuser or may write to a table of `app`, and refuse a check file that holds a backslash, so `psql` runs no meta-command from it. Their state files (`/var/lib/finance-deploy`) are data, parsed and never sourced; `rollback.sh` takes its commit from the operator and only compares it with the record. Nothing else in this rule changes. Decided after OPS-1's review (2026-10-02, by the PM) and built in F6b: the exception stays, with read-only a property of that role; a cancelled CI run refuses the deploy; a stop the owner judges harmless and a manual deploy are closed with `deploy/deploy.sh adopt`, which records the running revision as the last good deploy and touches no git, image, container or database.
- Never run a runbook section that changes state (restore, rotate, delete, update) as a test. It runs only when the task is to do exactly that.
- Production is read-only by default, unless the task says otherwise.

## Domain rules

1. The core model is a double-entry journal. A journal_entry has entry_date (DATE, no time zone), an optional payee (a counterparty), memo and kind. A posting belongs to one entry and has account, currency (ISO 4217 code), amount, optional category and optional counterparty.
2. Sign convention: debit is positive, credit is negative. For every entry and every currency, the sum of posting amounts is exactly zero.
3. Money is NUMERIC(19,4) in PostgreSQL and BigDecimal in Java, never float or double. Rounding to 2 decimals uses RoundingMode.HALF_UP and happens only where a rule says so; that holds for single amounts, such as conversions. Splitting an amount into shares (a family record, D-12) uses a sum-preserving rule instead: each share cut down to the currency's minor unit, the remainder to the largest share, on a tie to the payer, then by join order (`ledger.family.ShareSplit`).
4. Account types are ASSET, LIABILITY, EQUITY. Displayed balance: ASSET = sum of amounts; LIABILITY and EQUITY = minus sum of amounts. Of the Excel type LIABILITIES, UNALLOCATED and RESERVE map to EQUITY and all other accounts map to LIABILITY. System EQUITY accounts: OPENING_BALANCE and FX_EXCHANGE.
5. Categories have type INCOME or EXPENSE and may be set only on postings to EQUITY accounts. An expense is a positive posting to UNALLOCATED with an EXPENSE category; income is a negative posting to UNALLOCATED with an INCOME category. A refund uses the same category with the opposite sign and is valid.
6. An entry with at least one categorized posting is income or expense; an entry without categories is a transfer. The stored kind is only a hint for the UI; reports are always computed from postings.
7. Shared expense: total T is paid from one account; share ratio r defaults to 0.50. other = round(T × r, 2); own = T − other. Postings: payment account −T; UNALLOCATED +own with the category; the user's shared account (FAMILY_DEBT by default, configurable) +other.
8. Accounts with requires_counterparty = true (LOANS_ASSET and CREDITOR_DEBT) require a counterparty on every posting. Their balances are also reported per counterparty.
9. Currency exchange of amount A in currency X into amount B in currency Y: source account −A in X, FX_EXCHANGE +A in X, FX_EXCHANGE −B in Y, target account +B in Y.
10. Opening balances are posted against OPENING_BALANCE.
11. Every owned row has user_id equal to the Keycloak "sub" claim. Every query is scoped by it. Access to another user's object returns 404.
12. Accounts, categories and counterparties referenced by postings are archived, never deleted.
13. Values derivable from postings (month, year, account type, signed changes, loan sums, check columns) are never stored.
